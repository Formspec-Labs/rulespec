# Add selected span-bearing reference families

Decision: Is a five-family append-only reader worth a production proposal, or do its query assumptions still require upstream work?
Hypothesis: Keeping the current scan and appending SpicySearch candidates only for public_law, statutes_at_large, executive_order, docket and rin increases useful reference coverage without losing baseline observations or adding misleading identities. Counterhypothesis: family filtering alone does not prevent incomplete or context-free readings within those allowed families.
Arms: A = unchanged installed baseline scan; B = identical baseline result plus the existing detector's candidates restricted to the five named kinds. Raw unfiltered detector output is captured separately, never silently discarded. No new grammar, normalization, correction, deduplication or model call.
Cases: Replay the prior 32 development cases with their frozen labels; add at most 20 new cases fixed before running either arm, covering punctuation/Unicode, repeated occurrences, incomplete tokens, negative prose and two source excerpts if the preselected saved documents contain relevant citations. New constructed cases are diagnostics, not independent corpus coverage. Prior cases are development data; report old and new results separately. Selection of source excerpts is by explicit labels, not parser success. Preserve entire source documents and exact offsets for real excerpts.
Held constant: Exact input, baseline implementation, installed package versions, candidate fields and interpretation. One execution plus one replay. No provider calls, temperature or thinking configuration; no latency claim. Stop after these inputs or 20 minutes. No parser tuning in this run.
Measures: Baseline output equality, correct added occurrences, misleading added occurrences, failed/missed intended additions, exact source spans, duplicate-occurrence handling and preserved raw output. A repeated reference at a different span is a separate occurrence. Family detection does not prove legal existence or links to a real target. Whole-input status and token completeness must not be conflated.
Decision rule: A bounded integration proposal requires useful additions in at least three allowed families on development cases, no baseline changes, valid source spans for every added occurrence, no misleading additions on old or new cases, and recovery of every newly labeled positive occurrence. If the narrower gate fails, retain the failure and recommend the next distinguishing test or upstream change; do not quietly shrink the whitelist and call this gate passed. This experiment does not authorize production adoption or the separate RefSpec occurrence-API implementation.
