# Fresh local-reference repair generation

Decision: test whether focusing the existing recovery call on a complete native
reference group generates useful corrections on fresh inputs. Do not change
production behavior from this diagnostic alone.

Hypotheses: H1, the whole-source recovery task dilutes attention; marking a
complete referenced group as focus should improve repair generation. H2, the
existing edit/duplicate policy still treats separately retained meaning as
sufficient, so neither input generates the needed edits. H3, focus increases
edits but loses conditions or turns separate duties into prerequisites. The
observed proposals, including refused ones, distinguish these outcomes; they
do not reveal a model's hidden reasoning.

Sources selected before extraction: pinned USLM release 119-102, serialized
complete native excerpts through the existing reader. No current-law claim.
Repository research/example/evaluation search found no previous use of these
native subsection identifiers; provider training familiarity is unknown.

First make one ordinary production extraction of each fresh excerpt. Preserve
all raw outputs, refusals and original books. Read every extracted statement
before creating repair inputs and freeze that review before recovery calls.

For grants and pension, use the unchanged natural extraction if its targeted
default statement omits a criterion above. If that meaning is already complete,
a separate diagnostic copy may remove only the selected qualification from
that statement, retaining original evidence and separate records. Identify every
such edit and label it constructed. If there is no separate statement that can
be edited without discarding other independent meanings, keep the clean book
and report no repair opportunity. Do not search for replacement sources based
on extraction results. Reporting remains the unchanged extraction. Score
natural failures, constructed omissions and faithful controls separately.

Arms: A uses the complete excerpt as focus. B marks the fixed native group above
as focus and supplies every other source character as context. Both receive all
the same current claims, the same deterministic reference navigation and the
unchanged recovery instructions/schema. No hint identifies an expected missing
condition, no fixed repair is supplied, and no extra audit runs. This tests a
bundle of source focus and the existing restriction against editing context-only
claims. It cannot separate attention from that restriction. Preservation of
outside-focus records is partly enforced mechanically, not alone evidence of
semantic discrimination. Read raw refused proposals for attempted overreach.

Resolve focus through existing `SourceIndex`; obtain reference-to-claim material
through existing `context-export`. Preserve missing/ambiguous references. A
located link does not establish a governing relationship. Keep the same full
source in both arms and verify its interval coverage. Do not manufacture native
links, add a citation parser or relax the requirement qualification guard.

Four cases, two arms, one recovery call per cell. Randomize cell order and save
opaque IDs; review anonymized outputs before opening the arm key. Any decoded
proposals go to the unchanged checker with source evidence and to independent
temporary review previews. No reviews are applied to original runs. Rejected,
unknown, missing and mechanically refused outcomes remain visible. Read every
proposal, observation, check rationale and selected source span manually.

Held constant: gemini-3.8-flash, temperature 0. Initial production extraction
uses current low thinking and 16,384 output cap; both recovery arms and checks
use medium thinking, no numeric thinking budget, 32,768 output cap. Three initial
calls plus eight recovery calls and at most eight checker calls: 19 maximum,
no provider retries. Do not start a call after 1,200 cumulative capture seconds
or 250,000 reported tokens. An empty proposal list needs no checker request.
One sample per case/arm is exploratory, not a reliability estimate.

Gate for advancing to a larger evaluation: B must produce a source-faithful,
mechanically valid, checker-supported repair for each available primary missing
qualification in both fresh positive sources and the saved IEP case, preserve
all listed controls, and introduce no unsupported changes or explanatory facts.
If no natural fresh errors occur, report that natural repair quality is untested
regardless of constructed-case success. Measure actual A/B gain separately:
both passing shows no generation improvement from focus. Both failing means no
supported adoption, even if capture, schema and replay pass. Count accepted
repairs separately from useful-looking proposals rejected by the checker.

Freeze requests/runtime hashes, compare actual provider requests, replay with
model creation blocked, retain source provenance and save the decision and next
task. Stop at this bound without prompt patches. No production adoption or push.
