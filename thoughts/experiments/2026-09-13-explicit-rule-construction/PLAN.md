# Does an explicit construction task change the result?

Decision: determine whether asking for a complete default reading generates
faithful changes that ordinary recovery declines, with identical data and the
same full replacement schema. Experiment only; no production adoption.

H1: the recovery objective discourages expansion of separately retained meaning.
An explicit construction objective should generate useful edits while A remains
inactive. H2: the unchanged schema/data or other factors still inhibit meaningful
output; B will remain empty or fail. H3: B increases output by overcombining
related duties, changing conditions or inventing prerequisites. More output alone
does not support H1. If both fail, this test cannot separate schema burden,
reference-status ambiguity, task nonadherence or other remaining explanations.

Arms: both use current recovery, the same selected-statement restriction, full
source, all current claims and identical navigation. B alone receives the fixed
construction instruction in run.py, before the data. It defines self-contained
reading, explicitly permits incorporation of already recorded governing meaning,
and requests a source-based observation if no edit is warranted. This instruction
is evaluated as a task-definition bundle, not attributed to a single phrase.
Do not fix unresolved reference labels, trim empty fields, reorder the schema,
remove duplicate evidence, supply proposed replacement text or alter the checker.

The notice source is pinned USLM release 119-102, not a current-law claim. No
prior model use was found in searched research/example/evaluation paths. Read
its entire original extraction and freeze labels/selected aliases before paired
generation. If initial readings are already complete, retain them as faithful
controls and report no natural repair opportunity; do not plant an omission or
substitute another source after seeing the output. Existing book and source
artifacts remain immutable. No human-generated repair is sent to either arm.

A is a fresh contemporaneous control, not the historical no-op. Both arms now
have identical explicit selection restrictions, so A differs from the earlier
whole-book recovery task. Identical pension repeats measure variation on one
case, not new coverage. Randomize generation-cell order and use opaque labels;
save manual raw review before opening the arm key. Reviewers know source labels
and may infer an arm from response shape; this is not independent human blinding.

Reuse existing CUE-derived proposal schema, provider recorder, decoder,
unchanged source checker and ReviewStore previews. All decoded proposals are
checked, including those failing preview or requested edit scope. Original
snapshots/history are never changed. Preview each proposal independently;
successful previews do not demonstrate combined sequential application.

Model gemini-3.8-flash, temperature 0. One new extraction uses current production
low thinking/16,384 output cap. Eight generation calls and up to eight conditional
checker calls use medium thinking, no numeric budget, 32,768 cap. Maximum 17 calls,
no provider retries; no new call after 1,200 cumulative capture seconds or 220,000
reported tokens. Preserve failures and partial answers. Empty proposals skip the
checker. Stop without adding a prompt patch or rerunning a failed cell.

Report three separate measures: nonempty, compliant generation; manually checked
source-faithful standalone meaning; and unchanged-checker acceptance with valid
temporary preview. For pension, B must fix the selected reading in both repeats;
request/inspection must add only the correct request content and preserve all
negative controls; every actual notice gap must be repaired without the listed
overreach. False new duties, lost conditions, unjustified no-ops or inaccurate
source-based explanations fail the full gate. A useful edit rejected only as
duplication can support construction capability while failing the end-to-end gate.
No fresh improvement can be claimed if the new extraction has no repair gap.

Save exact requests, schemas, source/runtime pins, all responses/refusals, costs,
manual assessments and provider-blocked replay. Any narrower recommendation is
separate from a failed full gate. No new default pass, schema or qualification
guard change follows from this experiment alone.
