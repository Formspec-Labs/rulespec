# Existing relationship proposals before the existing audit

Decision: whether the existing relationship pass supplies useful dependency
information that lets the audit detect omitted remote qualifications. This is a
mechanism diagnostic on saved development data, not a fresh generalization test.
No production adoption, draft mutation or automatic approval.

Observation: both arms of explicit-audit-contrast recognized remote exclusions
separately yet accepted locally overbroad statements. Hypothesis: asking which
claims a qualification governs as a separate task will produce useful links;
supplying those links to the unchanged audit will improve detection. Alternatives:
the relationship task also misses links; links are found but the audit still
credits incomplete wording; incorrect links create false alarms. Distinguish
these outcomes instead of crediting the entire bundle to one cause.

Arms: A = fresh current audit on frozen draft and frozen inventory. B = the same
audit request plus decoded, unverified relationship suggestions from one separate
relationship call. That call uses refinement.RELATIONSHIPS, proposal_schema,
_packet, _proposal_prompt and _decode_proposals(stage='relationships') unchanged.
Use audit._capture to explicitly pin medium thinking for every call. No new
semantic schema, extra explanation field or hand-coded legal linking heuristic.
No prior audit verdicts are supplied to the relationship pass, only the same
source-first inventory, source and unchanged claims used in this experiment.

The appended B message identifies suggestions as fallible model output and tells
the auditor to verify applicability against source and judge the original draft.
It does not insert qualifications into the draft or treat a suggestion as a fix.
Retain all decoded proposals, unresolved observations and parser refusals; feed
only mechanically decoded proposals to B. No hand-selected winning suggestions.

Cases: reuse all three pinned documents, claims, labels and shared inventories
from ../2026-09-10-explicit-audit-contrast. Original seatbelts are provider output;
the four emergency-plan and four extinguisher claims are constructed diagnostics.
Preserve all four earlier planted defects and all four valid controls. No new
source selection or altered labels after outputs.

Target checks for relationship output:
- Extinguisher outside-building exemption and (b)(2) designated-user/evacuation
  exemption govern Class A distribution F0, not the general duty F1. F1 must
  retain the separate during-use exception and its existing broader scope.
- Seatbelt part 121/125/135 exclusions must reach the initial pilot duty, while
  the separate 91.105 exemption of paragraph (a)(3) must not reach pilot duties
  C0000/C0001. Qualifier wording such as "unless otherwise stated" must survive.
- Emergency-plan <=10 oral exception qualifies writing E1 and may not remove
  training E3. General required-plan applicability must survive.
- Every proposed target must exist; source must support its meaning and target.
  Uncertain interactions beyond these checks remain uncertain, not forced gold.

Held constant: original claims and inventories; same whole selected source,
24000-character window; gemini-3.8-flash, temperature 0, medium thinking, 32768
output tokens. Nine calls maximum: three relationship calls and six comparisons.
One relationship response per document is shared as the B input. No retries,
prompt patches or repairs. Randomize comparison order with seed 20260911. Stop
before a new call after nine calls or 20 minutes provider-stage elapsed time.
Do not interpret temperature zero as deterministic. One call per arm cannot
measure stability. Include the added relationship calls in cost, not just audits.

Before calls freeze source/draft/inventory hashes, runtime and exact prompts.
Record requests, outputs, model versions, decoding refusals and usage. Validate
that paired actual requests differ only by the proposal addition. Replay all
decoding and audit judgments from saved responses without model calls.

Decision rule: investigate broader transfer only if B detects BOTH previously
missed remote defects (extinguisher F0 and initial seatbelt duty) that fresh A
misses, retains detection of the three previously caught planted defects, creates
no new material false positives on valid controls, and does not rely on a false
relationship involving the named negative controls. A passing comparison is not
production approval. Any narrower improvement cannot rescue the full gate.
If A also catches a target, do not credit B with incremental detection there.
If the relationship map itself fails, classify the mechanism separately.

Manual assessment: read all proposed meanings/targets and every audit judgment
against source. Review numerical cell labels before opening the arm map where
practical; output can reveal the intervention, so not fully blind. Agent labels
are revisable. Assess mechanical validity, map quality, audit benefit, false
positives and token cost separately. Stop after the declared decision and replay.
