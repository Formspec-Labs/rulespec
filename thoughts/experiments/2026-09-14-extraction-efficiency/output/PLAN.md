# Optional output fields: omission instead of null placeholders

Decision: whether the existing extraction shape can reduce billed generation by making genuinely optional attributes absent unless substantive, while preserving complete statements and useful supporting structure.

Observation: Historical CSBG B emitted all 16 attributes on each of 282 records although only five are required. It emitted 2,288 optional empty/null values. Required actor and actor_quote uncertainty is excluded. Passage IDs already avoid billing expanded evidence copies. Optional-null guidance and complete-default statements are already production features; consistent omission is not established.

Hypotheses: (H1) Schema-permitted null placeholders encourage fixed-shape enumeration; disallowing null/empty values on optional properties should cause omission and reduce answer tokens. (H2) Sparse field selection requires more thinking or encourages fabricated content; answer savings may be offset by total generation or semantic regressions. (H3) Most remaining cost is meaningful statement/context wording and optional omission will have little effect. This two-case test separates observable outcomes, not hidden model reasoning.

Arms: A unchanged installed CUE-derived provider schema/prompt. B same schema semantics, titles, property order and guidance, but optional unit attributes are non-null/nonempty when emitted and are instructed to be omitted otherwise. Required actor and actor_quote remain nullable. Every available field remains available. The experimental transformation is generated from the current schema; no production change or parallel meaning schema.

Cases: Full CSBG section 9908 application-and-plan window (historical known omission: low-income beneficiaries and urban replication details); entire saved 29 USC1025(a) benefits excerpt as other-source counterexample containing real definitions, actors, timing, alternatives and exemptions. These are fresh calls on existing development documents, not an independent unseen benchmark. Review all generated meanings, 13 CSBG content requirements and beneficiary/replication details, benefits annual-notice alternative and 3-year rule, one-participant exception, Secretary vs administrator roles, definitions, and no false hard duty for descriptive/permission cases. Existing labels are revisable judgments.

Held constant: Installed pipeline capture/parser helpers, gemini-3.8-flash, low thinking, provider-managed sampling (temperature omitted), max_output_tokens 16384, one request per case/arm, no retries. Identical source windows/context per paired case. Exact raw SDK inputs and responses retained. Order CSBG A/B then benefits B/A to avoid a single fixed arm order. At most 4 fresh calls, 15 minutes total capture wall time, at most 65,536 allowed output tokens. No API checker/audit calls.

Decision rule: Further investigation only if B omits empty fields, decreases answer and total recorded generation tokens at least 10% pooled, retains useful populated fields, and has no material semantic loss compared with contemporaneous A. Adoption is not authorized by this small test; any suggested change must go through CUE with current parser compatibility. Regression or failure to improve => no production change. Mechanical validity, adherence, quality and consumption reported separately; observed missing content is not hidden by aggregate counts. Stop at four calls or the time bound; keep failures without retry.
