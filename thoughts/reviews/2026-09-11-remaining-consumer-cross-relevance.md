## Existing solutions that should be connected, not rebuilt

**Discovery already separates the useful pieces.** `discovery.py:19` exposes `source`, `summaries` and `packets`; packets retain the source passage text and connect claims through source/evidence overlap (`:32–47`). `export_discovery` keeps every source passage (`:52–85`), stores evidence once with role references (`:60–69`), emits statements and their qualification targets (`:87–109`), and includes reference candidates, rejected readings and located external evidence (`:110–138`). Full path: `packages/rulespec-extrapolator/src/rulespec_extrapolator/discovery.py`.

This gives R17 an existing result representation and R26 an existing evidence-table pattern. A small consumer can display a source hit, related statement, required local context and optional located target without concatenating all of them into every indexed passage. It must retain unresolved targets as such; evidence overlap does not establish that a condition governs a statement. The existing local BM25 comparison is callable at `packages/rulespec-extrapolator/evaluation/discovery_trial.py:28–63`. It is a lexical diagnostic, **not an embedding evaluation or production search backend**. Start there for deterministic wiring; any embedding benefit needs its own selected consumer and measured comparison.

**Feedback history exists, but its reading anchor needs attention.** `review_store.py:477–513` permits `observe` with no claim targets and preserves observation dictionaries; `:297–351` carries observations into snapshots and enrichment issues. `discovery.py:108` already exports those issues. That supports a narrow R18 reference-feedback record using existing history, with explicit source fragment, reading, reader provenance and optional target identity. It does not yet prove a complete reference correction UI or a rescan that resolves an earlier observation.

Accepted reference IDs use the source fragment, kind and value in `references.py:66`. Rejected rows return earlier at `:47–63` and lack that assigned candidate ID. A consumer must not drop rejected readings from feedback simply because they have no accepted ID. First define an anchor using the existing exact source evidence and distinguish the version of the reading being challenged; test repeated identical mentions and superseded readings. Avoid introducing a second global identity system. These files are under `packages/rulespec-extrapolator/src/rulespec_extrapolator/`.

Claim continuity is a separate, optional problem: `core.py:337–344` includes candidate order and run identity in claim/rule identities. The saved retention result reports 52 changed revision IDs, including 48 rule IDs, while preserving original reviews and leaving reprocessed output pending (`thoughts/experiments/2026-09-11-extraction-retention/README.md:36–46`). Do not make migrating approvals across reprocessing a prerequisite for gradual discovery feedback.

**Core already records the distinctions needed for a focused semantic trial.** `core.py:451–469` emits `supports`, `definesScope` and `providesContext` evidence roles; `:471–493` creates individual relationship assertions with qualification and target evidence. Local definition identity includes its source position and defining meaning (`terms.py:7–18`). Existing typed values retain comparators, units and reference events (`schema_data/document-understanding.cue:144–159`); `enrichment.py:35–57` deliberately supports only a small duration grammar. Reuse these for R16/R19/R22. A new explanation field or model-produced formula would add a second place to lose conditions.

**Optional investigation machinery exists, but the plan overstates its public granularity.** The CLI exposes `audit` and `refine` (`cli.py:79–103`). `audit_run` always records inventory and comparison (`audit.py:456–504`); `refine_run` wraps an initial audit, recovery, relationships and final audit (`refinement.py:471–551`). Private packet, prompt, proposal and judgment helpers are reusable, and an exact prior audit can be supplied. A source search found no standalone scenario callable in application Python/CUE. Thus R26 should say “reuse existing helpers in a bounded experiment,” not imply all three named checks already have independently callable production entry points.

There is already deliberate compression: `_challenge_catalog` deduplicates source intervals without joining gaps, and `_challenge_prompt` removes duplicate focus/context and duplicated proposal fields (`refinement.py:197–219`). Measure remaining duplication before editing it again. The existing public refinement loop should only gain a smaller route after that route demonstrates useful findings at lower cost.

## What the saved failures actually rule out

1. **Do not repeat source-plus-summary concatenation before ranking unchanged.** The experimental concatenation is at `thoughts/experiments/2026-09-10-design-retrieval/run.py:11–19`, not the production packet export. In the saved review, chlorine's required source falls from rank 1 to 20 and service/equipment support falls outside the top three (`RAW-REVIEW.md:15–16`). Combined text grows to 99,415 characters versus 15,928 source characters and repeats grouped meanings across hits (`:31`). The lexical comparison gives source and statements 14/16 relevant-fragment successes, combined 13/16 (`../2026-09-10-design-pilots/README.md:9`). Try separate result combination and evidence expansion; do not describe these scores as complete answers or embedding performance.

2. **Do not revive the failed context selector as unfinished adoption.** The fresh comparison records no gain on its three cases, a repeated authorization-to-obligation error and an incomplete response (`thoughts/experiments/2026-09-11-fresh-reference-context/README.md:34–52`). Its raw review identifies the actual title-20 `authority`/`may` → `authority`/`must` inconsistency despite “is authorized” evidence (`raw-review.md:126–136`), and title-38 beneficiary/actor variability (`:99–108`). Choose one different semantic intervention, such as preserving permission versus obligation, with fresh cases. The deterministic retention fixes recovered 112 occurrences from the same saved outputs but left seven kind/modality contradictions and the incomplete response (`../2026-09-11-extraction-retention/README.md:12–23`); that does not reverse the semantic result.

3. **Do not rerun bundled relationship verdicts plus generated descriptions as an isolated target test.** The retained raw result actually says “All other releases remain prohibited” (`thoughts/experiments/2026-09-10-design-targeted/cells/cell-00/result.json:49`) and declares the carrier prohibition “completely unaffected” (`cells/cell-05/result.json:28`). The source review explains the missing exemption/limits and disputed carrier interpretation (`RAW-REVIEW.md:7–23`). The 2/5 → 4/5 positive-link gain lost a previously expected service link. Clarify applicability context versus exception semantics first, then test independent verdicts without that extra prose. The current production checker still gives one verdict per proposal and requires every target to be supported (`refinement.py:80–99,124–126,514–528`); that is the precise bounded intervention seam. Per-target judgments cannot recover targets never proposed.

## Dependencies and sensible deferrals

- **R12/R23:** current `reference_sources.py:19–31` maps eligible explicit USC/CFR readings; `:34–85` indexes pinned XML sources and their native units. The concurrent eCFR integration should finish its application and installed-build checks before a consumer claims delivery. At this survey snapshot, the saved eCFR assessment expressly calls the extension source-tested and uninstalled (`thoughts/experiments/2026-09-11-ecfr-text/README.md:10–15`). This report does not verify installation. Source lookup and native structure make a better consumer possible; they do not establish historical correspondence or semantic gain. Broader paragraph-address and layout work belongs to a demonstrated missing source need, not every discovery result.
- **R20/R21/R22:** scope inventory to data a selected consumer can use. Publisher metadata can improve source selection or filtering independently of semantic model work. Local definitions and shared vocabulary suggestions must retain separate identities; a matching label does not establish the same legal sense. The [parallel source survey](2026-09-11-remaining-source-cross-relevance.md) identifies `AgencyProjection.build/resolve` as a bounded optional agency-candidate path, with ambiguity abstention, and recommends one verified Atlas read per release/run. It also finds that the existing Federal Register graph join takes the first matching proceedings row. Compare stated metadata with body observations before adopting those graph associations. Reuse those upstream readers rather than build another loader or registry here.
- **R8:** the graph path remains live: `packages/rulespec-projection/src/rulespec_projection/projection.py:802–807` reparses Unified Agenda strings through its own parser and mints affected CFR identities. Migrate that path if the chosen knowledge-link consumer needs those graph edges, preserving full ranges and refusal. It is not required for the existing discovery export. Avoid expanding R17 into a repository-wide parser migration.
- **R19:** no wos-spec/formspec adapter was found in the inspected application Python/CUE/package metadata. That is an implementation boundary, not proof those projects lack useful schemas. Prepare and review the concrete decision flow first; inspect the actual downstream schemas before mapping it. Keep unsupported actions, unknown conditions and omitted branches visible. Do not turn discovery approval into workflow approval.
- **R24:** use `evaluation.py:78–96,132–161,264–280` for source-pinned, revisable judgment accounting, with stale/unjudged results remaining unknown. `extraction.py:156–176` already counts recorded requests, usage and incomplete/unanswered responses; `:516–526` captures source and optional reader implementations. Fresh labels must assess complete meaning, not merely a selected quotation. The previous retrieval review explicitly found an under-specified de-minimis label (`design-retrieval/RAW-REVIEW.md:20–25`). Retain the old failed score rather than relabel it into a pass.

## Parallel work and stopping points

After the current source delivery settles, independently prepare: **(A)** a bounded R17 query/result comparison and reference-feedback example; **(B)** one R19 activity's source-only decision flow and representative scenarios; **(C)** R25 relationship semantics and fixed-target cases. The source survey can independently identify publication/vocabulary inputs for A. Share the R24 capture and review methods, not a mandatory sequence of model passes.

Adopt only the small consumer change that passes its declared comparison. Defer general cross-reprocessing identity continuity, all-family parser completion, graph migration without a graph consumer, universal model audits, and a broad workflow engine. A useful stopping point is one source-backed discovery result with persistent corrective feedback and one honestly reviewed preparation example; those make the value of further parser or semantic work concrete.
